## 背景

Task 002 已通过独立验收，但有以下遗留问题需要在本任务闭环：

1. 生产环境（`ENV=production`）仍会执行 `Base.metadata.create_all()`，
   与 Alembic 迁移职责重叠，会让运维误以为不需要跑 `alembic upgrade head`。
2. `.gitignore` 未忽略 `.pytest_cache/`，pytest 跑过会留下缓存目录。
3. 缺少「生产环境不调 create_all」的自动化测试。
4. 部署文档没有写清迁移与启动顺序。

## 目标

把迁移机制与生产环境启动路径彻底分离，确保：

- 生产环境部署流水线必须先 `alembic upgrade head`，再启动应用。
- 应用启动时不会隐式建表 / 改库。
- 非生产环境的开发体验保持不变。

## 生产环境行为

| ENV 值                  | 行为                                        |
| ----------------------- | ------------------------------------------- |
| `production`            | 跳过 `create_all`；期望运维已 `alembic upgrade head` |
| `PRODUCTION` / `Production` | 同上（大小写不敏感）                    |
| `development`           | 调用 `create_all`（默认兼容路径）           |
| `staging` / `test` / 其他 | 调用 `create_all`（兼容 dev / CI）         |
| 空字符串 / 未设置        | 调用 `create_all`（按 development 处理）    |

应用层其他行为（CORS、路由、文档开关）保持不变。
