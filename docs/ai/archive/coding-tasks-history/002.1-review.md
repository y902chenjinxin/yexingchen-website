## P1 后续整改项

### 1. 文档中的 fail-fast 表述与实际行为不符

独立测试使用 `ENV=production` 和全新空 SQLite 数据库导入 `app.main`：

- 进程返回码为 0。
- 应用成功导入。
- 未执行 `create_all`。
- 没有因为缺少业务表而启动失败。

因此“忘记执行 `alembic upgrade head`，应用启动会因为表不存在而失败”的表述目前不能作为事实。需要二选一：

- 方案 A（推荐）：在生产启动时增加明确的 Alembic 版本检查，未到 head 就拒绝启动；
- 方案 B：删除/改写文档中的必然 fail-fast 表述，只保证应用不自动建表，由实际请求在访问数据库时暴露问题。

### 2. 环境判断逻辑需要统一

`ensure_schema()` 使用 `.lower()` 判断生产环境，但 `docs_url` / `redoc_url` 仍直接比较原始 `ENV`。当 `ENV=PRODUCTION` 时，建表逻辑和 API 文档暴露逻辑不一致。需要统一使用规范化后的环境值，并补测试。
