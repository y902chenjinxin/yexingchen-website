## 背景

Task 002.1 已实现：`ENV=production` 时跳过启动时的 `Base.metadata.create_all()`。

独立验收发现：使用空 SQLite 数据库导入 `app.main` 时，应用仍然可以成功导入，因此当前并没有真正实现“数据库未迁移时 fail-fast”。此外，schema 判断已经对 `ENV` 做了小写归一化，但 `/docs` 和 `/redoc` 的判断仍直接使用原始环境变量，存在大小写行为不一致。

## 目标

1. 生产环境启动时检查数据库是否已经迁移到当前 Alembic head。
2. 生产数据库未迁移、版本落后、版本不匹配或存在多个 head 时，应用启动失败。
3. 生产数据库已迁移到唯一当前 head 时，应用正常启动。
4. `ENV=production`、`ENV=PRODUCTION`、`ENV=Production` 的 schema、docs、redoc 行为一致。
5. 非生产环境保持现有行为：允许 `create_all`，不要求迁移版本检查。
6. 不新增玄黄工作台业务表或业务接口。

## 推荐实现边界

### 环境值

在 `main.py` 或最小公共位置定义规范化环境值，例如：

```python
env = os.environ.get("ENV", "development").strip().lower()
is_production = env == "production"
```

schema、`docs_url`、`redoc_url` 必须使用同一个规范化后的判断结果。

### 生产 schema 检查

生产环境在创建 FastAPI app 前执行 schema 检查：

- 读取当前数据库连接中的 Alembic revision。
- 获取迁移脚本中的唯一 head。
- 当前数据库 revision 必须存在且等于唯一 head。
- 没有 `alembic_version`、没有 revision、revision 落后、revision 不匹配或存在多个 head 时，抛出清晰异常并拒绝启动。
- 日志中提示先执行：

```text
alembic upgrade head
```

- 日志和异常中不得包含数据库密码、连接串中的敏感信息或其他凭证。

可以使用 Alembic/SQLAlchemy 官方 API 实现，不要通过脆弱的 shell 文本解析判断版本。

### 非生产环境

- development / staging / test / 空字符串 / 未设置 ENV：继续调用 `Base.metadata.create_all()`。
- 现有 `test_api.py` 和迁移测试必须保持通过。

## 必须新增/修改的测试

测试不能只检查源代码字符串，必须验证运行行为。

至少覆盖：

1. `ENV=production` + 空数据库：导入 `app.main` 失败，并提示 `alembic upgrade head`。
2. `ENV=production` + 已执行 `alembic upgrade head` 的数据库：导入 `app.main` 成功。
3. `ENV=production` + 数据库 revision 落后或不匹配：导入失败。
4. `ENV=production` + 多 head（如果当前迁移结构可构造）：导入失败；如果无法在本任务可靠构造，说明原因并至少测试唯一 head 检查。
5. `ENV=production` / `PRODUCTION` / `Production`：docs 和 redoc 都保持关闭。
6. 非生产环境：现有 `create_all` 参数化测试仍全部通过。

测试应使用临时 SQLite 数据库或其他隔离测试数据库，不能改动开发数据库。
