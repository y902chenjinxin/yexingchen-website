## 产品目标

把现有个人网站逐步完善为“玄黄”个人工作台：

```text
想法
→ 富文本笔记
→ 图片/PDF/网页附件
→ 分类和标签
→ 全局搜索
→ AI 整理/摘要/标签/任务
→ 轻量任务跟进
```

## 总体约束

- 在现有 Vue 3 + Vite + Pinia + Element Plus + Axios 前端上增量开发。
- 在现有 FastAPI + SQLAlchemy + SQLite 后端上增量开发。
- 保留 `/home` 和现有音乐、小说、视频、日志、工具模块。
- 不删除旧模块，不大规模重构旧模块。
- 单用户场景，不实现团队协作、多租户和复杂权限。
- MVP 文件存储使用服务器本地磁盘，并通过 StorageService 隔离存储实现。
- MVP PWA 必须联网，不实现离线编辑和同步。
- 云端 AI 供应商暂未确定，使用可替换 Provider 接口；不要把具体供应商或真实 API Key 写死。
- 不连接生产服务器。
- 不执行生产数据库迁移。
- 不推送 GitHub。
- 不使用真实密码、Token、API Key 或生产数据库。
- 不把 mock 数据冒充真实业务完成状态。
- 不全量格式化旧代码。

## 内部执行阶段

### 阶段 0：基线与迁移接管

1. 完成生产 schema 保护：
   - production 环境不执行 `Base.metadata.create_all()`；
   - 检查数据库 Alembic revision 是否匹配唯一 head；
   - 空库、未迁移、落后或不匹配时 fail-fast；
   - 已迁移到 head 时允许启动；
   - `production` 大小写形式行为一致；
   - `/docs`、`/redoc` 使用同一规范化环境判断。
2. 保证非生产环境现有测试和开发启动行为不被破坏。
3. 确认 Alembic 是新增 schema 的唯一生产入口。
4. 增加或修正 `.gitignore`，忽略 Python 测试缓存、数据库和虚拟环境。

### 阶段 1：工作台壳层、路由和 PWA

1. 新增登录保护路由 `/workbench`。
2. 登录成功后进入 `/workbench`。
3. 保留 `/home` 和全部旧路由。
4. 工作台首页包含：
   - 快速记录；
   - 全局搜索入口；
   - AI 助手入口；
   - 今日任务；
   - 最近编辑；
   - 待整理草稿；
   - 分类和标签入口；
   - 旧模块入口。
5. 新增建议路由：
   - `/notes`
   - `/notes/:id`
   - `/assets`
   - `/tasks`
   - `/assistant`
   - `/trash`
6. 页面使用“玄黄”名称，沿用现有视觉体系，不重做完整品牌设计。
7. 支持桌面和手机宽度，不出现明显横向溢出。
8. 增加 PWA manifest：名称使用“玄黄”。
9. 增加基础 Service Worker，只缓存静态壳和稳定资源。
10. 不缓存认证 API、私人数据和 AI 响应。
11. Service Worker 注册失败不能阻塞应用启动。

### 阶段 2：笔记和富文本编辑

1. 新增 Note 数据模型、迁移、Schema、Repository/Service、API 和前端 Store。
2. 笔记字段至少包括：
   - title
   - content
   - status：`draft` / `completed`
   - summary，可为空
   - created_at
   - updated_at
   - completed_at，可为空
   - deleted_at，可为空
   - user_id
3. 实现笔记列表、创建、编辑、删除、恢复。
4. 编辑中的笔记自动保存为草稿。
5. 页面显示保存中、已保存、保存失败。
6. 点击“完成”后变成正式笔记。
7. 草稿和正式笔记都可以继续编辑。
8. 自动保存必须防抖，不能每次输入都请求接口。
9. 处理保存请求竞态，较旧响应不能覆盖较新内容。
10. 富文本至少支持：
    - 标题
    - 加粗、斜体、下划线
    - 文字颜色
    - 有序/无序列表
    - 引用
    - 代码块
    - 网页链接
    - 图片
    - PDF 附件
    - 撤销/重做
11. 图片支持：
    - 点击上传
    - 剪贴板粘贴
    - 拖拽上传
12. 不实现复杂表格、多人协作、评论、版本对比和实时协同。
13. 富文本内容必须安全渲染，避免 XSS；不要直接信任未经清洗的 HTML。

编辑器具体库可以由 Coding 模型根据现有依赖和维护成本选择，但必须说明选择原因，并避免引入不必要的大型依赖。

### 阶段 3：网页、图片和 PDF 资产

1. 新增 Asset 数据模型、迁移、Schema、Service、API 和前端页面。
2. 资产类型：
   - `link`
   - `image`
   - `pdf`
3. 网页 MVP：
   - 保存 URL
   - 标题
   - 备注/描述
   - 标签
   - 独立查看和打开
   - 不做正文抓取
4. 图片 MVP：
   - 本地磁盘上传
   - 预览
   - 下载
   - 标题/描述/标签
   - 可插入笔记
   - 不做 OCR
5. PDF MVP：
   - 本地磁盘上传
   - 在线预览或下载
   - 标题/描述/标签
   - 可关联笔记
   - 不做文字提取和 OCR
6. 存储通过 `StorageService` 接口封装，业务代码不能直接散落操作文件系统。
7. 文件物理路径使用不可预测的安全名称；原始文件名仅作为元数据保存。
8. 文件下载和预览必须经过当前用户权限校验。
9. 后端再次校验：
   - 图片扩展名、MIME 和内容；
   - PDF 扩展名、MIME 和内容；
   - 文件大小；
   - 路径安全；
   - 用户权限。
10. 限制：
    - 单张图片最大 10 MB；
    - 单个 PDF 最大 50 MB；
    - 单条笔记附件总量最大 200 MB。
11. 超过限制时返回明确错误，前端显示具体原因。
12. 一条笔记可关联多个网页、图片和 PDF；资产也可以独立存在。
13. 不重新接入已删除的旧 COS 桶；保留未来 COS Provider 的扩展边界。

### 阶段 4：标签、分类和搜索

1. 新增 Tag、NoteTag、AssetTag 数据模型和迁移。
2. 标签支持：
   - 自由输入；
   - 多标签；
   - 选择已有标签；
   - 删除关联；
   - 按标签筛选。
3. 固定内容类型：笔记、网页、图片、PDF、任务。
4. 不实现复杂文件夹层级。
5. 全局搜索支持：
   - 笔记标题；
   - 笔记正文；
   - 笔记摘要；
   - 网页标题和 URL；
   - 图片标题和描述；
   - PDF 标题和原始文件名；
   - 任务标题和描述；
   - 标签。
6. 第一版不搜索 PDF 内文、图片文字和网页正文。
7. 搜索接口分页，避免一次返回全部数据。
8. 搜索结果必须经过用户权限过滤。

### 阶段 5：轻量任务

1. 新增 Task 和内容关联模型、迁移、API、Store 和页面。
2. 字段：
   - title
   - description
   - status：`todo` / `doing` / `done`
   - priority：`low` / `medium` / `high`
   - due_date，可为空
   - completed_at，可为空
   - created_at
   - updated_at
   - deleted_at，可为空
   - user_id
3. 支持手动创建任务。
4. 支持从笔记、网页、图片或 PDF 创建任务。
5. 支持修改状态、优先级、截止日期和描述。
6. 支持关联笔记或资产。
7. 工作台展示今日任务和逾期任务。
8. 不实现多人协作、甘特图、审批流和复杂项目层级。

### 阶段 6：AI 助手和对话记录

1. 新增 AI Provider 抽象和配置层。
2. 业务代码只依赖统一服务接口，不绑定单一供应商。
3. 配置通过服务器环境变量：
   - `AI_PROVIDER`
   - `AI_BASE_URL`
   - `AI_MODEL`
   - `AI_API_KEY`
   - `AI_TIMEOUT`
4. 不把真实配置写入前端、代码、测试或 Git。
5. 如果暂时没有真实供应商配置，测试使用 fake provider；不要伪造真实调用成功。
6. MVP AI 能力：
   - 整理富文本笔记；
   - 生成摘要；
   - 提取建议标签；
   - 从笔记生成任务草稿。
7. AI 只处理用户主动触发或主动选择的内容。
8. 调用前显示本次发送内容范围。
9. 后端再次过滤密码、Token、私钥和明显敏感配置。
10. AI 返回结果先作为建议，用户确认后才写入笔记、摘要、标签或任务。
11. 删除、批量修改、部署、推送等高风险操作不由 MVP AI 自动执行。
12. 新增 AiConversation、AiMessage 和必要关联模型、迁移、API、Store 和页面。
13. 对话默认保存。
14. 对话支持：
    - 自动标题；
    - 修改标题；
    - 关联笔记/资产/任务；
    - 搜索；
    - 删除。
15. 删除对话不删除原始笔记、资产或任务。
16. 对话内容和发送范围不能记录 API Key 或其他密钥。
17. 第一版不做基于多资料的复杂问答、PDF 总结、图片理解、网页正文分析和自动抓取。

### 阶段 7：回收站、清理和日志

1. 笔记、资产、任务和 AI 对话删除时进入回收站。
2. 回收站保留 30 天。
3. 30 天内支持恢复。
4. 支持用户确认后永久清理。
5. 自动清理任务物理删除过期文件和关联记录。
6. 清理失败需要记录错误，不影响其他内容清理。
7. 记录上传、删除、恢复、永久清理、AI 应用结果等操作日志。
8. 删除操作和永久清理需要前端二次确认，后端不能只依赖前端。
9. 不实现备份；这是用户已明确接受的风险。

### 阶段 8：文档、测试和工程卫生

1. 更新安装和开发文档。
2. 更新 API 说明。
3. 更新数据库迁移说明。
4. 更新回滚说明。
5. 更新 CHANGELOG 或新增版本记录。
6. 所有新增数据库表必须使用 Alembic migration。
7. 不依赖生产启动时 `create_all` 创建新表。
8. 新增后端测试：
   - 模型和迁移；
   - CRUD；
   - 权限；
   - 文件类型和大小限制；
   - 软删除、恢复和清理；
   - 搜索；
   - AI fake provider；
   - 敏感信息过滤；
   - 生产 schema 检查。
9. 新增前端测试：
   - 路由和登录跳转；
   - 工作台页面；
   - 自动保存状态；
   - 任务状态；
   - PWA 注册不阻塞。
10. 不追求本批次全量修复旧 lint 问题，但新增代码不能明显增加 lint error。
11. 清理测试数据库、缓存、`__pycache__` 和临时文件。

- 需要改变产品范围或删除旧模块；
- 需要改变 SQLite 以外的生产数据库；
- 需要重新创建云存储并产生费用；

- 需要推送 GitHub 或部署；
- 发现现有数据结构无法安全迁移。
