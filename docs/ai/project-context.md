## 已确认的工作台方向（2026-08-27）

- 产品最终方向：A，现有网站逐步转为个人工作台。
- 核心使用流程：想法 → 写成笔记 → 添加图片/视频/文件等附件 → 加标签 → 搜索 → AI 整理 → 必要时转成任务。
- MVP 文件存储：服务器本地磁盘；架构上保留存储服务抽象，未来可切换到对象存储。
- AI 权限边界：接受默认方案。读取、搜索、总结、分类、生成草稿和任务单可自动执行；删除、批量修改、部署、GitHub 推送、数据库结构修改、对外发送等必须先确认；密码、Token、私钥等敏感信息不得直接展示或提交。

## 已确认的内容范围（2026-08-27）

- 旧模块处理：音乐、小说、视频、日志、工具继续保留，不删除。
- 工作台 MVP 必须支持：富文本笔记、网页链接、图片、PDF。
- 可以后做：视频、音频统一纳入工作台内容资产。
- 暂不做：小说纳入统一工作台内容资产。
- 首页：接受默认方案，包括快速记录、全局搜索、AI 助手、今日任务、最近编辑、待整理、分类和标签入口。
- 富文本：笔记需要富文本编辑能力；具体编辑器方案待技术评审。
- 轻量任务：已纳入 MVP，用于承接笔记和想法中的后续行动。

## 轻量任务已纳入 MVP（2026-08-27）

- 状态：已确认
- 决策：MVP 纳入轻量任务/待办功能。
- 作用：将笔记或想法转化为后续行动，不做复杂项目管理。
- 暂定字段：标题、描述、状态、优先级、截止日期、关联内容。

## 内容资产 MVP 行为已确认（2026-08-27）

- 一条富文本笔记可以关联多个网页、图片和 PDF 附件。
- PDF MVP：保存、预览、下载、标题/描述/标签；暂不做文字提取和 OCR。
- 网页 MVP：保存 URL、标题、备注和标签；暂不做自动抓取正文/摘要。
- 图片 MVP：上传、预览、下载、标题/描述/标签；暂不做 OCR 或 AI 图片理解。
- 网页抓取、PDF 文本提取、扫描 PDF OCR、图片 OCR 和自动摘要列为后续能力。

## 收藏功能暂不纳入 MVP（2026-08-27）

- 状态：已确认
- 决策：MVP 暂不做收藏功能。
- 原因：当前为单用户，分类、标签、搜索、最近编辑和任务已经足够；避免与重要/置顶概念重复。
- 后续：根据实际内容规模再评估收藏或置顶。

## 笔记保存方式已确认（2026-08-27）

- 状态：已确认
- 决策：笔记采用自动保存草稿 + 手动完成的方式。
- 流程：先快速记录并自动保存为草稿，后续继续编辑；点击“完成”后成为正式笔记，再进行 AI 整理或转成任务。

## 富文本编辑器范围已确认（2026-08-27）

- 编辑器：采用默认 MVP 功能，包括标题、常用文字格式、列表、引用、代码块、链接、图片、PDF 附件、撤销/重做。
- 图片添加：支持点击上传、粘贴剪贴板图片和拖拽图片。

## 文件限制与回收站规则已确认（2026-08-27）

- 单张图片最大 10 MB。
- 单个 PDF 最大 50 MB。
- 单条笔记附件总量最大 200 MB。
- 删除采用回收站，暂定保留 30 天后自动清理。

## 云端 AI 方案已确认（2026-08-27）

- 状态：已确认
- AI 采用云端 API，不在 MVP 阶段部署本地模型。
- 仅在用户主动触发时处理内容，不默认上传全部资料。
- 发送前展示将要发送的内容范围。
- 密码、Token、私钥等敏感信息不得发送给 AI 服务。
- AI API Key 只放服务器环境变量，不进入前端或 GitHub。
- 具体 AI 服务供应商待确认，接口设计应保留可替换性。

- 状态：待确认

## AI 对话保存策略已确认（2026-08-27）

- 状态：已确认
- AI 对话默认保存到本地工作台，用户可以修改标题、关联内容、关联任务、搜索和删除。
- 删除 AI 对话不自动删除原始笔记、附件或任务。

## AI MVP 能力已确认（2026-08-27）

- 第一优先级：整理富文本笔记。
- 第二优先级：生成摘要。
- 第三优先级：提取标签。
- 第四优先级：从笔记生成轻量任务。
- 后续能力：基于选定资料问答、内容改写、PDF 总结、图片理解、网页正文分析。

## 备份策略已确认（2026-08-27）

- 状态：已确认，风险接受
- MVP 暂不做自动备份或手动备份流程。
- 图片、PDF 和其他上传文件仅保存于服务器本地磁盘。
- 服务器故障、磁盘损坏或误操作可能导致数据永久丢失。
- 回收站只用于防普通误删，不视为备份方案。
- 后续：当资料重要性或数量增加时重新评估备份。

## Coding 模型协作自动化目标（2026-08-27）

- 用户希望减少自己在当前助手与 Trae Code/Coding 模型之间手动传话。
- 当前分工：当前助手负责设计、任务拆解和独立验收；Coding 模型负责代码实施。
- 当前已确认：本机 PATH 和常见安装目录未发现可调用的 Trae/Trae Code 命令，因此尚未建立直接进程/API/MCP 连接。
- 推荐过渡方式：共享工作区任务单 + Coding 模型结果文件 + 当前助手自动读取 diff 和测试结果。
- 若 Trae 提供可调用 CLI/API/MCP/文件监听接口，再评估全自动触发和结果回传。
