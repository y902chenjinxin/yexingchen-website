## 1. 产品概述

### 1.1 产品名称

玄黄

### 1.2 产品定位

玄黄是一个单用户个人工作台，用于把零散想法沉淀为笔记、内容资产和可执行任务，并在用户主动触发时使用云端 AI 进行整理。

### 1.3 产品目标

1. 快速记录想法，降低记录成本。
2. 统一管理富文本笔记、网页链接、图片和 PDF。
3. 用分类、自由标签、搜索和最近编辑组织内容。
4. 把笔记中的后续行动转成轻量任务。
5. 通过云端 AI 完成笔记整理、摘要、标签提取和任务生成。
6. 在不破坏现有网站的前提下逐步扩展。

### 1.4 用户

- 当前用户：用户本人，单用户。
- 当前不做：团队、多用户协作、多租户、公开分享权限。

## 3. 页面与核心流程

### 3.1 页面建议

| 路由 | 页面 | MVP 职责 |
|---|---|---|
| `/workbench` | 工作台首页 | 快速记录、搜索、AI、任务、最近编辑、待整理 |
| `/notes` | 笔记列表 | 筛选、搜索、创建、编辑、删除/恢复 |
| `/notes/:id` | 笔记详情 | 富文本编辑、附件、标签、AI 操作、转任务 |
| `/assets` | 内容资产 | 网页、图片、PDF 的列表和管理 |
| `/tasks` | 任务 | 创建、状态切换、优先级、截止日期、关联内容 |
| `/assistant` | AI 助手 | 对话、内容选择、调用确认、历史记录 |
| `/trash` | 回收站 | 查看、恢复、永久清理 |
| `/home` | 原浮空岛首页 | 保留旧入口和旧模块 |

> 路由名称是当前建议，Coding 模型实现前需确认是否采用。

### 3.2 核心流程：快速记录

1. 用户进入 `/workbench`。
2. 点击“快速记录”。
3. 创建一条草稿笔记。
4. 输入标题和富文本内容。
5. 自动保存草稿并显示保存状态。
6. 添加网页、图片或 PDF。
7. 添加分类和标签。
8. 点击“完成”成为正式笔记。

### 3.3 核心流程：AI 整理

1. 用户打开一条笔记。
2. 点击“AI 整理”。
3. 系统展示将发送给云端 AI 的内容范围。
4. 用户确认调用。
5. AI 返回整理结果、摘要和建议标签。
6. 用户选择是否应用结果。
7. 如识别出后续行动，用户选择是否创建任务。

### 3.4 核心流程：回收站

1. 用户删除笔记或资产。
2. 系统标记为已删除并移入回收站。
3. 用户可在 30 天内恢复。
4. 超过 30 天由清理任务删除文件和关联记录。

## 4. 权限与安全边界

### 4.1 可自动执行

- 读取工作台内容。
- 搜索内容。
- 总结和整理用户主动选择的内容。
- 建议标签。
- 生成任务草稿。
- 生成 Coding 模型任务单。
- 查看本地项目测试结果。

### 4.2 必须先确认

- 删除内容。
- 批量修改内容。
- 应用 AI 返回的批量变更。
- 永久清理回收站。
- 修改数据库结构。
- 修改服务器配置。
- 执行部署或回滚。
- 推送 GitHub。
- 发送邮件或对外发布。

### 4.3 禁止

- 在界面或对话中直接展示密码、Token、私钥等敏感值。
- 将敏感值提交到 GitHub。
- 未确认执行不可逆外部操作。
- 默认把全部私人资料发送给云端 AI。

## 5. 数据与存储原则

- 数据库沿用现有 SQLite 方向，新增功能必须通过可追踪迁移，不直接依赖生产环境 `create_all`。
- 文件存储第一版使用服务器本地磁盘。
- 需要封装存储服务接口，未来可切换对象存储。
- 文件路径和原始文件名分离保存；实际磁盘名使用不可预测的安全名称。
- 删除采用软删除，回收站清理后才物理删除。
- 所有上传、删除、恢复、永久清理和 AI 应用变更记录操作日志。

## 6. 非功能要求

- 安全：后端二次校验文件类型、大小和权限；不能信任前端校验。
- 可用性：自动保存不应静默丢失；保存失败必须给出明确提示。
- 性能：列表接口分页；大文件不读入内存后再保存；前端附件上传显示进度。
- 兼容性：桌面优先，同时适配手机浏览器；PWA 必须联网。
- 可维护性：新增工作台代码与旧模块边界清晰；不全量重构旧模块。
- 可回滚：数据库迁移和文件变化需要有回滚/补偿方案。
