# 项目决策记录

## 2026-08-27：产品名称确定为“玄黄”

- 状态：已确认
- 决策：工作台名称使用“玄黄”。
- 原因：与个人工作台定位和现有水墨国风视觉方向一致。

## 2026-08-27：个人工作台方向

- 状态：已确认
- 决策：现有个人网站最终逐步转为个人工作台。
- 核心流程：想法 → 笔记 → 附件 → 标签 → 搜索 → AI 整理 → 转任务。
- 存储：MVP 使用服务器本地磁盘，同时保留存储抽象以便未来切换 COS 或其他对象存储。
- AI 权限：接受默认边界；高风险和不可逆操作必须先确认。
- 影响：优先设计统一内容资产和任务入口；旧音乐、小说、视频、日志、工具模块先保持兼容。

## 2026-08-27：MVP 内容类型和旧模块策略

- 状态：已确认
- 决策：保留现有音乐、小说、视频、日志、工具模块；新增工作台独立入口。
- MVP 必须支持富文本笔记、网页链接、图片和 PDF。
- 视频、音频后续支持；小说暂不纳入统一工作台。
- 首页采用快速记录、搜索、AI、今日任务、最近编辑、待整理和收藏的默认信息架构。
- 任务功能是否进入 MVP 尚未确认；如进入，仅做轻量任务，不做复杂项目管理。

## 2026-08-27：轻量任务纳入 MVP

- 状态：已确认
- 决策：MVP 加入轻量任务/待办功能。
- 目的：承接笔记和想法中的下一步行动。
- 范围：手动创建、从内容创建、状态跟踪、优先级、截止日期、内容关联。
- 限制：不做复杂项目管理和多人协作。

## 2026-08-27：内容资产关联和 MVP 行为

- 状态：已确认
- 决策：采用内容资产模型，一条笔记可关联多个网页、图片和 PDF；附件也可独立存在。
- MVP 暂只做保存、预览/下载、元数据、标签和关联，不做网页抓取、PDF 文本提取、OCR 或自动摘要。

## 2026-08-27：收藏暂不纳入 MVP

- 状态：已确认
- 决策：第一版不实现收藏或置顶。
- 原因：单用户场景中标签、分类、搜索和最近编辑足够，减少重复能力。

## 2026-08-27：笔记自动保存草稿

- 状态：已确认
- 决策：富文本笔记采用自动保存草稿、手动点击完成的流程。
- 原因：符合先记录想法、后续整理的使用习惯，降低忘记保存导致内容丢失的风险。

## 2026-08-27：富文本编辑器和图片输入

- 状态：已确认
- 决策：采用默认 MVP 富文本能力；图片支持点击上传、粘贴和拖拽。
- 原因：满足日常记录和网页截图整理，同时控制第一版复杂度。

## 2026-08-27：文件大小和回收站策略

- 状态：已确认
- 决策：图片 10 MB、PDF 50 MB、单条笔记附件总量 200 MB。
- 决策：删除先进回收站，默认保留 30 天后清理。
- 原因：个人工作台需要控制本地磁盘占用，同时避免误删导致数据立即丢失。

## 2026-08-27：AI 使用云端 API

- 状态：已确认
- 决策：MVP 采用云端 AI API，不部署本地模型。
- 边界：主动触发、发送前确认范围、敏感信息拦截、Key 仅服务器保存。
- 架构：保留 AI Provider 抽象，供应商可替换。

## 2026-08-27：AI 供应商暂不决定

- 状态：待确认
- 决策：暂不绑定具体云端 AI 供应商，先设计 Provider 抽象。
- 原因：保留选择空间，避免早期供应商锁定。

## 2026-08-27：AI 对话默认保存

- 状态：已确认
- 决策：AI 对话默认保存，支持改标题、关联内容、搜索和删除。
- 删除对话不删除原始笔记、附件和任务。
- 原因：保留长期工作记录，同时允许用户清理无用对话。

## 2026-08-27：AI MVP 能力优先级

- 状态：已确认
- 决策：AI MVP 先做笔记整理、摘要、标签提取和任务生成。
- 原因：直接服务于已确认的“想法 → 笔记 → 整理 → 行动”主流程。

## 2026-08-27：MVP 暂不备份

- 状态：已确认，风险接受
- 决策：第一版不做自动备份或手动备份，文件只存服务器本地。
- 原因：先控制 MVP 复杂度和成本。
- 风险：服务器故障或磁盘损坏可能导致数据永久丢失。

## 2026-08-27：登录后进入工作台

- 状态：已确认
- 决策：登录后进入 `/workbench`；现有 `/home` 保留。
- 原因：工作台承担日常工作入口，同时保护现有浮空岛页面和旧模块投资。

## 2026-08-27：多端路线暂定

- 状态：暂定
- 建议：先做响应式 Web + PWA，后续用 Capacitor 扩展 Android/iOS，桌面 App 后置。
- 原因：最大化复用现有 Vue/Vite 前端，避免 MVP 同时维护多套客户端。
- 待确认：具体平台和原生能力需求。

## 2026-08-27：MVP 优先 PWA

- 状态：已确认
- 决策：MVP 先做响应式网页和 PWA，不开发独立原生 App。
- 原因：复用现有 Vue/Vite 项目，控制开发范围和维护成本。

## 2026-08-27：PWA 必须联网

- 状态：已确认
- 决策：MVP PWA 必须联网，只做安装和基础缓存，不做离线编辑或同步。
- 原因：降低第一版复杂度，避免引入本地数据同步和冲突处理。
